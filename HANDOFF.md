# Передача сайта разработчикам

Документ для команды, которая будет вести сайт дальше.

## Что это

Маркетинговый сайт JGGL. Одна страница, статическая: HTML, CSS и немного
JavaScript. Ни React, ни Next, ни сборщика — зависимостей у проекта нет
вообще, `npm install` ставит ноль пакетов.

Сделан по макету «JGGL Site V4» из Claude Design. Вёрстка, отступы, цвета,
типографика и анимации перенесены из макета один в один.

- **Репозиторий:** https://github.com/jgglentertainment/jgglentertainment.github.io
- **Живой сайт:** https://jgglentertainment.github.io/

## Что нужно знать в первую очередь

**`public/index.html` генерируется скриптом.** Править его руками нельзя —
изменения затрёт следующая сборка. Тексты живут в `build/data.js`, оттуда
`build/generate.js` собирает готовый HTML.

Так сделано намеренно: в исходном макете все списки (навигация, форматы,
FAQ, таблица сравнения, плитки футера, бегущие строки) рисовались на
клиенте через шаблонизатор. Для маркетинговой страницы это плохо для SEO и
первого рендера, поэтому списки разворачиваются на этапе сборки, а
`app.js` навешивает только поведение. Страница читается и без JavaScript.

**Всё лежит в репозитории.** Страница не делает ни одного стороннего
запроса: фотографии, видео, логотипы, шрифты и иконки отдаются с того же
адреса, что и сама страница. Раньше медиа грузилась с `jggl.ai` (это AWS
в США), и на части сетей она не открывалась — страница работала, а картинки
не появлялись. Поэтому всё перенесли в `public/assets/media/`.

## Структура

```
public/                  то, что реально отдаётся браузеру
  index.html             ГЕНЕРИРУЕТСЯ — руками не править
  styles.css             токены, раскладка, адаптив
  app.js                 поведение: выбор формата, печатающийся текст,
                         FAQ, скроллспай, бургер, модалка
  assets/                иконки, логотипы, шрифты, фавиконы
  assets/media/          фотографии, видео, логотипы брендов
build/
  data.js                ВСЕ ТЕКСТЫ И СПИСКИ САЙТА
  generate.js            собирает public/index.html из data.js
  standalone.js          опционально: однофайловая версия со всем внутри
render.yaml              конфиг на случай переезда на Render
```

## Как запустить локально

```bash
git clone https://github.com/jgglentertainment/jgglentertainment.github.io.git
cd jgglentertainment.github.io
python3 -m http.server 4321 --directory public
```

Открыть http://localhost:4321 — этого достаточно, сборка для просмотра не
нужна, `public/index.html` уже лежит в репозитории.

## Как править

| Что меняем | Где |
|---|---|
| Тексты, пункты FAQ, строки таблицы, ссылки | `build/data.js` |
| Цвета, отступы, адаптив | `public/styles.css` |
| Поведение элементов | `public/app.js` |
| Структуру блоков | `build/generate.js` |

После правки `build/data.js` или `build/generate.js` обязательно:

```bash
npm run build
```

## Как публиковать

```bash
npm run build
git commit -am "описание правки"
git push origin main
npm run publish
```

`npm run publish` пересобирает `public/` и выталкивает его в корень ветки
`gh-pages` — оттуда GitHub Pages раздаёт сайт. Изменения видны через
30–60 секунд.

## Как устроен хостинг

GitHub Pages, бесплатно.

- ветка `main` — исходники
- ветка `gh-pages` — собранный сайт в корне, её и раздаёт Pages
- файл `public/.nojekyll` обязателен: без него GitHub прогоняет папку через
  Jekyll и отдаёт отрендеренный README вместо сайта

Репозиторий публичный — на бесплатном плане GitHub Pages иначе не работает.

## Подключить свой домен

Когда появится домен (например `jgglentertainment.ai`):

1. Settings → Pages → Custom domain в репозитории
2. У регистратора: четыре A-записи на `185.199.108.153`, `185.199.109.153`,
   `185.199.110.153`, `185.199.111.153`; CNAME `www` →
   `jgglentertainment.github.io`
3. Добавить файл `public/CNAME` с доменом внутри — иначе следующий
   `npm run publish` перезапишет ветку и настройка слетит
4. Если домен на Cloudflare — проксирование выключить (серое облако),
   иначе GitHub не выпустит SSL-сертификат

## Что стоит сделать дальше

Это не поломки, а осознанные компромиссы — решать команде:

1. **Автоматизировать деплой.** Сейчас публикация — ручная команда. Можно
   повесить GitHub Actions на push в `main`; потребуется токен со scope
   `workflow`.
2. **Шрифт Scoutie Sans.** Это брендовый шрифт, в макет он не входил. Сейчас
   он первым в стеке и подхватится, если появится; пока подставляется
   Instrument Sans.
3. **Аналитика.** Не подключена.
4. **Вес медиа.** Папка `public/assets/media/` занимает 7.3 МБ, несколько
   webp тяжелее 500 КБ. Их можно пережать без заметной потери качества.

## История

Прежний адрес `https://vasilevaxco.github.io/jggl-site/` — первый вариант
деплоя, пока тоже работает. Репозиторий: `vasilevaxco/jggl-site`. Держать
две копии одного сайта в поиске нежелательно, старую стоит отключить:
Settings → Pages → Unpublish site.

На Render сайт не разворачивали: он требует привязку банковской карты даже
для бесплатной статики. `render.yaml` в репозитории оставлен — build
`npm run build`, publish `public`. Те же настройки подойдут для Cloudflare
Pages и Netlify, они карту не требуют.
